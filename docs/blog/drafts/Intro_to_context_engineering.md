AI being used for coding, simply dumping the code base to the LLM and asking it do the job for you will not scale well. The current vibe-coding hype may work well for bootstrapping an idea or developing an MVP. But the same concept will not work well for seasoned projects like Linux kernel. Because the code base is vast with multi-level abstractions. There will be links traversing across hundreds of files.

In scenarios like this, LLMs will usually stuck in build-fix loop - After making a change, it will try to build the project, hit by an error, then try to solve the error and go back to build. This loop will take multiple iterations and will cause a context hijacks (usually called as hallucinations). Aiding the AI with the relevant information upfront will not only increase the success ratio but also will reduce your cost drastically.

Take an IDE like VSCode. When you rename a variable, it will automatically underline all it's references providing a visual cue for the developer to look out. These kind of identifications are implemented by special tool which are spawned out of compiler tech. The initial passes of the compilers are built into separate tools and used for analysis here. The recent trend in LLM coder tool creating companies is repurposing these tools and aiding the LLM with a proper feedback loop.

LLVM is one of a developer friendly project which is adapted my many folks recently. Though it was initially developed as a compiler collection, many lexical, syntactic and semantic tools got spawned out of the project.
