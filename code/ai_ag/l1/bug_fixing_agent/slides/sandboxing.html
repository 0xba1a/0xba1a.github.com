The Threat: "What if?"

⚠️ Scenario 1: Agent decides to clean up disk space...

rm -rf /  # Oops, there goes the OS

⚠️ Scenario 2: Agent needs a password...

cat /etc/shadow  # Exfiltrating secrets

⚠️ Scenario 3: Infinite Loop...

while True: fork()  # Fork bomb crashes the server

The Solution: Sandboxing

  • Isolation: Run the agent's code in a disposable environment (Docker, Firecracker VM).
  • Restriction: Limit network access, file system access, and resource usage.
  • Ephemeral: Spin up, run task, tear down. No state persists.

"The Agent is the Virus, the Sandbox is the Quarantine."

        super().__init__(..., folder_to_mount=folder_mount_info)

2. The Interface (Hands)

The Host talks to a Shell Server running inside the container via REST API.

Reference: src/microbots/environment/local_docker/LocalDockerEnvironment.py

def execute(self, command: str) -> CmdReturn:
    # The container runs a server listening on port 8080 (mapped to self.port)
    url = f"http://localhost:{self.port}/execute"
    
    try:
        # Send the command to the sandbox via HTTP POST
        response = requests.post(url, json={"cmd": command}, timeout=timeout)
        
        # Receive stdout/stderr from the sandbox
        result = response.json()
        return CmdReturn(
            stdout=result.get("stdout", ""), 
            stderr=result.get("stderr", ""), 
            return_code=result.get("return_code", 0)
        )
    except requests.exceptions.RequestException as e:
        logger.error("❌ Request failed: %s", e)

3. Overlay Filesystem (Code)

Implementation using Linux overlayfs.

Reference: src/microbots/environment/local_docker/LocalDockerEnvironment.py

def _setup_overlay_mount(self):
    # 1. Create 'upper' (writable) and 'work' directories
    mount_command = (
        f"mkdir -p {overlay_path}/upper {overlay_path}/work && "
        
        # 2. Mount overlay: 
        #    lowerdir = Read-Only Original Code
        #    upperdir = Writable Layer
        f"mount -t overlay overlay -o "
        f"lowerdir=/ro/{path_name}/,"
        f"upperdir={overlay_path}/upper/,"
        f"workdir={overlay_path}/work/ "
        f"{self.folder_to_mount.sandbox_path}"
    )
    
    # Execute the mount command inside the container
    self.execute(mount_command)

4. Internal Server (The Ear)

A FastAPI server inside the container listens for commands and executes them via a Shell Communicator.

Reference: src/microbots/environment/local_docker/image_builder/dockerShell.py

from fastapi import FastAPI
from ShellCommunicator import ShellCommunicator

# Initialize persistent shell session (bash)
shell = ShellCommunicator("bash")
shell.start_session()

app = FastAPI()

@app.post("/")
async def receive_message(message: Message):
    # 1. Receive command from Host
    # 2. Execute in persistent shell
    command_output = shell.send_command(message.message)
    
    # 3. Return stdout/stderr back to Host
    return {"status": "success", "output": command_output}

The Container Gap

Traditional Containers:

  • Share the Host Kernel.
  • Isolation relies on namespaces & cgroups.
  • ⚠️ Kernel panic in container = Host crash.
  • ⚠️ Kernel exploit = Host compromise.

Bins/Libs

Hardware

Enter Kata Containers

"The speed of containers, the security of VMs."

  • Uses Hardware Virtualization (VT-x).
  • Each container/pod runs in its own Lightweight VM.
  • Uses a dedicated Guest Kernel.
Compatible with Docker & Kubernetes (OCI Compliant)

Key Takeaways

  • Never run agent code on your host machine.
  • Use Docker for basic isolation.
  • Use Kata Containers for VM-level security.
  • Control file access with Mounts.
