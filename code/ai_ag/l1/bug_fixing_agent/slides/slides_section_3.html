Cost Management

  • Infinite Loops: Agents getting stuck.
  • Token Overruns:Too many input or output tokens in every API calls
  • Excessive thinking:Too many reasoning steps lead to higher cost on thinking tokens
  • Hallucination: Making up commands or files.
  • Drift: Straying from the original goal.

Preventing Infinite Loops

Always enforce a hard limit on the number of execution steps.

       START
         │
         ▼
   ┌─────────────┐              ┌──────────┐      ┌───────────────┐
 ┌─► Step > Max? │ ────NO───►   │ Run Agent│ ───► │Increment Step │ ──┐
 │ └──────┬──────┘              └──────────┘      └───────────────┘   │
 │        │ YES                                                       │
 │        ▼                                                           │
 │   ┌──────────────┐                                                 │
 │   │ STOP / ERROR │                                                 │
 │   └──────────────┘                                                 │
 │                                                                    │
 └────────────────────────────────────────────────────────────────────┘

Why? Agents can get stuck in loops (e.g., repeatedly trying to fix a file and failing). A step limit prevents runaway costs.

Case Study: The $700 Bug

SWE-agent/issues/1240

Scenario: User set a $4 cost limit per instance.

Outcome: A single step cost >$700.

Root Cause: Gemini 2.5 Pro generated 72 million reasoning tokens in one API call.

Lesson: "Thinking/Reasoning" tokens are often billed as output tokens but might not respect standard output token limits. Always verify how your provider counts and limits reasoning tokens.

Monitoring Token Usage

Example with Google Gen AI SDK


response = model.generate_content(
    "Solve this complex problem...",
    generation_config={
        "thinking_config": {
            "include_thoughts": True,
            "thinking_budget_token_limit": 4096 # Limit thinking tokens
        }
    }
)

# Access usage metadata
usage = response.usage_metadata
print(f"Input Tokens: {usage.prompt_token_count}")
print(f"Output Tokens: {usage.candidates_token_count}")
print(f"Total Tokens: {usage.total_token_count}")

# Check for reasoning tokens
if usage.candidates_tokens_details:
    print(f"Thinking: {usage.candidates_tokens_details.reasoning_token_count}")

Reference: Google Gemini API - Setting Thinking Budget

Tip: Implement a budget check after every step. If total_cost > limit, stop the agent immediately.

Live Grading & Early Stopping

Implementing the Reflection Pattern with a cost function.

The Problem: Agents can "drift" or hallucinate while thinking they are making progress.

The Solution: A "Live Grader" (Critic) evaluates every step.

Grade = Quality_Score - (Step_Penalty × Step_Count)

  • Quality_Score: LLM assessment of the current state (0-100).
  • Step_Penalty: Cost per step (e.g., 5 points).
  • Cutoff: If Grade < Threshold, ABORT.

Live Grading Flow

      START
        │
        ▼
  ┌────────────┐
  │ Agent Step │◄──────────────────────────┐
  └─────┬──────┘                           │
        │                                  │
        ▼                                  │
  ┌────────────┐                           │
  │   Grader   │ (Score = Q - Penalty*N)   │
  └─────┬──────┘                           │
        │                                  │
        ▼                                  │
  ┌────────────┐      NO (Keep Going)      │
  │ Score < Min?├──────────────────────────┘
  └─────┬──────┘
        │ YES (Drifted/Too Expensive)
        ▼
  ┌────────────┐
  │    ABORT   │
  └────────────┘
The loop continues only if the agent maintains a high enough quality score relative to the cost (steps).

KV Cache & Prompt Caching

How LLM servers reuse computation to save costs and latency.

Concept: The "Key-Value Cache" stores the processed state of the prompt prefix. If the start of your prompt is identical to a previous request, the server reuses the cache.

System Prompt (Cached)

Static instructions, tools, few-shot examples.

"You are an AI agent..."
"Tools: [read_file, ...]"
User Prompt (Uncached)

Dynamic, instance-specific details.

"Fix bug in file.py..."
"Error: Line 10..."

Strategy: Keep the System Prompt generic and static. Put all variable data in the User Prompt.

Safety & Restrictions

LLMs have two interfaces:

  1. API Parameters: Temp, Top-P (Deterministic control).
  2. NLP in Prompt: "Do not delete files" (Softer control).
Action Restrictions:
Never allow raw `rm -rf` or `sudo` without strict sandboxing or human-in-the-loop.
