What is a Token?

The fundamental unit of text for an LLM is not a "word" but a token.

A token can be:

  • A whole word (e.g., "apple")
  • A part of a word (e.g., "ing" in "playing")
  • A single character (e.g., "a")

Rule of Thumb:
1000 tokens ≈ 750 words

Example

Text: "Tokenization is fun!"


Tokens:

[
  "Token",
  "ization",
  " is",
  " fun",
  "!"
]

Note: Spaces are often included in the token.

How Words Become Tokens

LLMs use sub-word tokenization to balance vocabulary size and flexibility.

Common Algorithms

  • BPE (Byte-Pair Encoding):
    Used by GPT-2, GPT-3, Llama.
    Method: Iteratively merges the most frequent pair of adjacent characters.
  • WordPiece:
    Used by BERT.
    Method: Similar to BPE but chooses merges that maximize the likelihood of the training data.

Importance of Tokenization

Why Sub-word?

It allows the model to handle rare words or misspellings by breaking them down into known sub-parts.

"unfriendly" → "un" + "friend" + "ly"


Importance of Good Tokenization:

If "friend" was split into "fri" + "end", the model might focus on "end" and lose the context of friendship.

Special Tokens

Tokens that provide structural instructions to the model.

Token Name Function
[BOS] / <s> Beginning of Sequence Signals the start of input.
[EOS] / </s> End of Sequence Tells the model to stop generating.
[PAD] Padding Makes batches same length (ignored).
[SEP] Separator Separates sentences (e.g., in Q&A).

Embeddings: From Tokens to Vectors

Computers don't understand text; they understand numbers.

Embedding: A process of converting a token into a dense vector (a list of floating-point numbers).

These vectors are learned during the model's training.

"King"  -> [ 0.12, -0.45,  0.88, ...]
"Queen" -> [ 0.14, -0.42,  0.91, ...]
"Apple" -> [-0.85,  0.22, -0.11, ...]

(Real vectors have 768, 1536, or 4096 dimensions)

Key Concept: The position of the vector in space represents its meaning.

The Vector Space & Meaning

Semantic Similarity: Concepts with similar meanings are located close to each other in the vector space.

^ | (King) (Queen) | * * | | | (Man) (Woman) | * * | +-------------------------->

Vector Arithmetic:

$\vec{King} - \vec{Man} + \vec{Woman} \approx \vec{Queen}$

The relationship (direction/distance) between "Man" and "King" is similar to "Woman" and "Queen".

Vector Databases

Traditional databases (SQL) search for exact matches (e.g., WHERE id = 5).

Vector Databases are optimized to store and query high-dimensional vectors.

Why do we need them?

  • To store the "knowledge" (embeddings) of millions of documents.
  • To perform Semantic Search: Finding data based on meaning, not just keywords.

Examples: ChromaDB, Pinecone, Milvus, Weaviate, pgvector.

How Vector Search Works

We want to find the "Nearest Neighbors" to a query vector.

Similarity Metrics

  • Cosine Similarity: Measures the angle between vectors. (Most common for text).
  • Euclidean Distance (L2): Measures the straight-line distance.

Indexing (HNSW)

Comparing a query to every vector is too slow.

HNSW (Hierarchical Navigable Small World): A graph-based index that creates "highways" between points for fast Approximate Nearest Neighbor (ANN) search.

The Problem with LLMs

LLMs are powerful, but they have limitations:

  1. Knowledge Cutoff: They only know what they were trained on. They don't know about events that happened yesterday.
  2. Hallucination: When they don't know the answer, they might confidently make one up.
  3. Private Data: They don't know your company's private emails or documents.

Solution: Give the LLM the right context before it answers.

RAG (Retrieval-Augmented Generation)

Concept: Augmenting the LLM prompt with relevant context retrieved from a Vector DB.

[User Query] | v [Vector Search] <---> [Vector DB (Your Data)] | (Relevant Context) | v [Prompt Augmentation] "Use this context: ... to answer: ..." | v [LLM] | v [Answer]

The RAG Workflow

  1. Ingest:
    • Load documents (PDF, CSV, etc.).
    • Split into Chunks.
    • Generate Embeddings for chunks.
    • Store in Vector DB.
  2. Retrieve:
    • User asks a question.
    • Convert question to vector.
    • Search Vector DB for top $k$ similar chunks.
  3. Generate:
    • Feed Context + Question to LLM.
    • LLM generates accurate answer.
