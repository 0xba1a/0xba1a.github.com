# YouTube Shorts Presentation — Animation Learnings

## Project Structure
- Each short lives in `presentation/shorts_<topic>/` with `index.html`, `style.css`, `script.js`, `plan.md`
- `plan.md` contains: voiceover script (~150 words for 60s), scene-by-scene plan with visual/animation notes, color scheme, original raw script
- Serve locally: `python3 -m http.server 8765` from the short's directory
- Reference existing shorts: `shorts_latency_vs_response_time/` (CSS-only sequence diagram), `shorts_avg_median_percentile/` (D3.js bar chart)

## Aspect Ratio & Safe Zones
- YouTube Shorts: 9:16 (1080×1920). Use CSS `aspect-ratio: 3/4` with `width: min(75vh, 100vw)`
- **YouTube button overlay buffer**: 10-14% horizontal padding on left/right, 8-10% top, 18%+ bottom
- **Facecam zone**: Bottom-left ~28% width square — keep clear of critical content (but don't render a placeholder unless asked)
- Bottom-right is safe for step counter / HUD

## Font Sizing for Mobile (IMPORTANT)
- **DO NOT use `vw` units** for fonts inside `#stage`. The stage uses `min(75vh, 100vw)` so on desktop it shrinks (75vh < 100vw) and `vw` no longer tracks stage size — text becomes tiny or huge inconsistently.
- **Use container query units (`cqw`) instead**: Set `#stage { container-type: inline-size; }` and size fonts with `cqw`. 1cqw = 1% of stage width — scales perfectly across devices.
- Typical sizes: hook title `10-11cqw`, section heading `6-7cqw`, body `4-5cqw`, HUD/CTA `2.5-3.5cqw`
- **SVG text**: Inside a `viewBox` like `0 0 600 600`, text scales with viewBox. On a 360px-wide phone stage, the viewBox shrinks ~0.6× → 12px text renders at 7px (too small). Use 18-22px in SVG to compensate.

## Click-Through State Machine Pattern
- Use a step counter with debounce (350ms) to prevent double-clicks
- Pattern: `const steps = [null, step1, step2, ...]; steps[currentStep]()`
- Reset function must clear ALL state: CSS classes, D3 elements, JS variables
- Keyboard: ArrowRight/Space to advance, ArrowLeft/R to reset
- Show step counter at bottom: `${currentStep} / ${TOTAL_STEPS}`
- On last step: change hint text to "← Tap to restart"
- Wrap everything in an IIFE: `(() => { ... })()`

## CSS Animation Approach (simpler shorts like sequence diagrams)
- Use CSS classes (`.visible`, `.dimmed`, `.active`) toggled by JS step handlers
- `transition: opacity .5s ease` for fade-in/out, `transition: max-height .6s ease` for vertical growth
- `transform: scaleX(0)` → `scaleX(1)` with `transform-origin` for arrow line animations
- Scene switching: all scenes are `position: absolute; inset: 0; opacity: 0; pointer-events: none`, `.active` sets `opacity: 1; pointer-events: auto`
- CSS `overflow: visible` is needed on containers whose children have labels positioned outside (otherwise labels get clipped)

## D3.js Animation Approach (data-driven shorts like charts)
- Load D3 v7 via CDN: `<script src="https://d3js.org/d3.v7.min.js"></script>`
- Use SVG `viewBox` for responsive sizing: `svg.attr('viewBox', '0 0 ${W} ${H}').attr('preserveAspectRatio', 'xMidYMid meet')`
- Initialize chart lazily on the step that first shows it (not on page load) — container may not have dimensions yet

### Scale Selection
- `d3.scaleLinear`: Normal data. Avoid when outliers are 100x larger — small bars become invisible
- `d3.scaleSqrt()`: Best for data with outliers (response times). Compresses top, expands bottom — small bars visible, outliers still dramatic
- `d3.scaleBand()`: For categorical x-axis (individual requests). Use `.padding(0.15)` for spacing

### Bar Chart Animations
- **Staggered entry**: `.delay((d, i) => i * 30).duration(500)` — bars grow up one by one
- **Object constancy**: `.data(data, d => d.idx)` key function so bars maintain identity during sort
- **Sort animation**: Recompute `xScale.domain()` with sorted order, then `.transition().duration(800).attr('x', d => xScale(d.idx))` — bars slide into place
- **Random initial order**: Use a deterministic seeded shuffle for reproducibility. Don't use `Math.random()` — it differs per reload
- **Combining steps**: When merging animations (e.g., sort + p50 line), delay the second with `.delay(900)` after an 800ms sort
- **Dimming bars**: `.transition().duration(400).style('opacity', 0.3)` for de-emphasis, 0.7 for semi-emphasis

### Lines and Annotations
- **Horizontal line sweep**: Start at `x2=0`, transition to `x2=width` over 700ms
- **Vertical line drop**: Start at `y2=height`, transition to `y2=0` over 500ms
- **Labels**: Fade in after line with `.delay(400-500ms).duration(300).attr('opacity', 1)`
- **Dashed lines**: `stroke-dasharray: 8 4` for avg, `6 3` for SLO

## Label Positioning — Avoiding Overlaps
- Place labels at **different y-positions** (e.g., p50 at y=14, p99 at y=30, SLO label at `sloY - 8`)
- Use `text-anchor: end` vs `start` to place labels on opposite sides of vertical lines
- For horizontal lines (avg, SLO), put labels at opposite ends (`x=4` left-aligned vs `x=width-4` right-aligned)
- Annotation text (e.g., "Worst 1%") should use a **contrasting color** (bright yellow `#ffd700`) when overlapping colored bars
- If a label extends past chart margins, switch `text-anchor` direction or add more margin

## Data Design for Educational Presentations
- **Percentiles with small datasets**: With ≤30 data points, `Math.floor(n * 0.99)` = last index — not useful for p99
- Solution: Find the semantic boundary (e.g., last bar before outliers) and use that as p99 position
- Educational presentations prioritize **concept clarity over mathematical precision**
- For response time data: ~26 normal values (20-140ms range) + 4 outlier values (2000-10000ms) = 30 bars works well visually
- Hardcode data for reproducibility — don't generate randomly at runtime

## Voiceover Script Guidelines
- Target ~150 words for a 60-second short
- Keep sentences short and punchy for mobile viewers
- VO text overlays are optional — user prefers NO on-screen VO text (will record voice separately)
- If VO text is used, position at bottom with text-shadow for readability over chart content

## Common Pitfalls
- `overflow: hidden` on containers clips child labels positioned outside — use `overflow: visible`
- CSS `transition` on strikethrough: position the strikethrough element INSIDE the target word's span, not as a sibling
- D3 `remove()` after `transition()` needs `.end()` or chaining — just use `.transition().attr('opacity', 0).remove()` which removes after transition
- Don't rely on `Math.random()` for data order — different every reload, hard to debug
- When using `writing-mode: vertical-rl` for rotated bracket labels, test actual rendering — it behaves differently across browsers
